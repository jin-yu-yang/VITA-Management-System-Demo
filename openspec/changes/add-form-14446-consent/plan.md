# Add Form 14446 Consent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Every client consents to PCDC's virtual VITA process at 0.4, which unlocks the rest of the form.
- Every client signs Form 14446 at 1.5, with the spouse under rule J; the signing dates fill themselves.
- The client and staff can view a draft Form 14446, filled from the answers, in English and 繁體.
- The seeded samples stay complete.

**Architecture:**
- **The catalogue:** two new catalogue sections; Section 15 holds `vc_agree` in "Before you start", and Section 16 the signatures in "About you". They are generated into migration 029.
- **The gate:** a gate in `resolveSubstep` (`src/intake-form.mjs`), which every move and every drawn page already goes through, plus a locked rail and a disabled Continue in `src/intake-views.mjs`.
- **The dates:** the controller fills them in `editAnswers`.
- **The draft:** a new field map, `src/draft-14446-form.mjs`, over XFA-stripped copies of PCDC's PDFs, built by the existing `buildDraftPdf`.
- **The samples:** a hand-written migration, 030, gives them their 14446 answers.

**Tech Stack:**

- `node:test`;
- the Markdown catalogue drafts and `tools/build-intake-catalogue.mjs`;
- `pdf-lib` (and fontkit) for the drafts;
- Supabase/Postgres (local stack `vitally-task2`);

```js
// Writes the draft Form 14446 forms (openspec change add-form-14446-consent,
// design D5): PCDC's own copies in docs/media without their XFA layer, so
// pdf-lib opens them without its "Removing XFA form data" console warning,
// and with page 3's Yes/No boxes cleared ("Request to Review your Tax Return
// for Accuracy" and "I agree to use this site's Virtual VITA/TCE Process"), so
// the client's answers decide them. Run it once when PCDC's
// copies change; the outputs are committed and pinned by SHA-256.
import { readFile, writeFile } from "node:fs/promises";
import { PDFDocument, PDFName } from "pdf-lib";

const FORMS = [
  {
    from: "docs/media/f14446 - Taxpayer.pdf",
    to: "src/forms/f14446-pcdc-en.pdf",
    clear: ["consentYes[0]", "consentNo[0]", "amAgreeingTo[0].agreeingYes[0]", "amAgreeingTo[0].agreeingNo[0]"].map((box) => `form1[0].page3[0].${box}`),
  },
  {
    from: "docs/media/f14446 - 主报税人.pdf",
    to: "src/forms/f14446-pcdc-zh-t.pdf",
    clear: ["yes[0]", "no[0]", "I_am[0].yes[0]", "I_am[0].no[0]"].map((box) => `form1[0].page3[0].${box}`),
  },
];

for (const { from, to, clear } of FORMS) {
  const doc = await PDFDocument.load(await readFile(from));
  const acro = doc.catalog.lookup(PDFName.of("AcroForm"));
  acro?.delete(PDFName.of("XFA"));
  doc.catalog.delete(PDFName.of("NeedsRendering"));
  const form = doc.getForm();
  for (const name of clear) form.getCheckBox(name).uncheck();
  // A fixed date keeps the output byte-identical from run to run.
  const fixed = new Date(Date.UTC(2026, 0, 1));
  doc.setModificationDate(fixed);
  doc.setCreationDate(fixed);
  await writeFile(to, await doc.save({ useObjectStreams: false }));
  console.log(`wrote ${to}`);
}
```

  If pdf-lib's API names differ (for example, if removing the XFA requires `form.acroForm.dict.delete`), adapt the lines and say so in your report. The goal is that `PDFDocument.load(bytes).getForm()` on the outputs logs nothing.
