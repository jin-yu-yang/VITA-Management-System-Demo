# Add Widowed Spouse Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A widowed client whose spouse died in 2023, 2024 or 2025 gives the spouse's name and date of birth, under the sub-step title "Your late spouse" / 已故配偶.
- A 2025 death also gives:
  - the spouse's job title and optional race question;
  - "My spouse" in the who questions;
  - the married wording;
  - the spouse's Photo ID and SSN cards;
  - the late-spouse direct-deposit hint;
  - the draft 13614-C's spouse lines.
- The spouse's phone, the Form 15080 spouse signature, `married_last_day` and `lived_apart_last_6mo` stay married only.
- `spouse_death_year` accepts 1900–2025 only.

**Architecture:**
- **The show-if language** gains `gte`, `lte` and `any`:
  - the browser's `holds()` and the database's `vitally_private.intake_holds` evaluate them the same way;
  - a hand-written migration, 027, teaches the database, the loader and the year check;
  - the generated catalogue migration, 028, follows it.
- **Two named rules** are defined once in the catalogue builder:
  - S `spouse_on_return`: married, or widowed with a death from 2023 to 2025;
  - J `joint_possible`: married, or widowed with a death in 2025.

  A draft writes `` rule `name` ``; the builder expands it.
- **Readers.** `spouseShown` becomes J and the new `spouseOnReturn` is S. The cards, the controller's spouse clean-up, the Fill, the draft 13614-C and the sub-step title read them.

- **The condition kinds:**

- [ ] **Step 3: Implement `holds`**

  In `src/intake-catalogue.mjs`, replace `holds` with:

```js
// A whole number written in ASCII digits without a leading zero, else null.
// gte and lte read only these, as the database's intake_holds does (change
// add-widowed-spouse-rules): "02025", which the year check refuses, never
// counts as 2025.
const wholeNumber = (value) => (typeof value === "string" && /^(0|[1-9][0-9]*)$/.test(value) ? Number(value) : null);

const holds = (condition, answers) => {
  if (condition.op === "any")
    return (condition.groups ?? []).some((group) => group.every((inner) => holds(inner, answers)));
  const value = answers?.[condition.field];
  if (condition.op === "filled") return filled(value);
  if (condition.op === "gte" || condition.op === "lte") {
    const n = wholeNumber(value);
    return n !== null && (condition.op === "gte" ? n >= condition.value : n <= condition.value);
  }
  const same = Array.isArray(value) ? value.includes(condition.value) : value === condition.value;
  if (condition.op === "eq") return same;
  if (condition.op === "ne") return filled(value) && !same;
  return false;
};
```

  Create `supabase/migrations/027_intake_show_if_any_and_year_range.sql`. Copy `intake_holds` from `supabase/migrations/011_intake_v2.sql` (~lines 294–313) verbatim, adding only the `gte`, `lte` and `any` branches:

```sql
-- OpenSpec change add-widowed-spouse-rules (design D1, D3, D4): the show-if
-- language gains `gte`, `lte` and `any`, and a year can carry a range.
--
--   * intake_holds: verbatim from 011_intake_v2.sql, with the `gte`, `lte`
--     and `any` branches added. gte/lte hold only for a string holding a whole
--     number without a leading zero ("02025" never counts as 2025);
--     `any` holds when one of its groups (each an AND list) holds.
--   * intake_show_if_ok: new. put_intake_field's show-if check, recursive
--     through `any`.
--   * put_intake_field: verbatim from 015_intake_loader.sql, with its last
--     refusal (the op list) replaced by a call to intake_show_if_ok.
--   * check_intake_value: verbatim from 015_intake_loader.sql, with the year
--     branch reading min_value and max_value.
--
-- The catalogue migration that uses them (028) comes after this one: 015's
-- put_intake_field refuses `any`. Every statement can be applied again.

create or replace function vitally_private.intake_holds(p_show_if jsonb,p_merged jsonb) returns boolean
language sql immutable security definer set search_path='' as $$
 select coalesce(pg_catalog.bool_and(
  case c->>'op'
   when 'filled' then vitally_private.intake_answered(p_merged->(c->>'field'))
   when 'eq' then coalesce(case when pg_catalog.jsonb_typeof(p_merged->(c->>'field')) = 'array'
    then (p_merged->(c->>'field')) @> pg_catalog.jsonb_build_array(c->'value')
    else (p_merged->(c->>'field')) = (c->'value') end, false)
   when 'ne' then vitally_private.intake_answered(p_merged->(c->>'field'))
    and not coalesce(case when pg_catalog.jsonb_typeof(p_merged->(c->>'field')) = 'array'
     then (p_merged->(c->>'field')) @> pg_catalog.jsonb_build_array(c->'value')
     else (p_merged->(c->>'field')) = (c->'value') end, false)
   when 'gte' then case when pg_catalog.jsonb_typeof(p_merged->(c->>'field')) = 'string'
     and (p_merged->>(c->>'field')) ~ '^(0|[1-9][0-9]*)$'
    then (p_merged->>(c->>'field'))::numeric >= (c->>'value')::numeric else false end
   when 'lte' then case when pg_catalog.jsonb_typeof(p_merged->(c->>'field')) = 'string'
     and (p_merged->>(c->>'field')) ~ '^(0|[1-9][0-9]*)$'
    then (p_merged->>(c->>'field'))::numeric <= (c->>'value')::numeric else false end
   when 'any' then exists(select 1 from pg_catalog.jsonb_array_elements(coalesce(c->'groups', '[]'::jsonb)) g
    where vitally_private.intake_holds(g, p_merged))
   else false end), true)
 from pg_catalog.jsonb_array_elements(coalesce(p_show_if, '[]'::jsonb)) c
$$;
```

  The digit test sits inside a `case`, so the cast never sees non-digits. Postgres does not promise the order of `and`, but a `case` is evaluated in order.

- [ ] **Step 2: Add `intake_show_if_ok`**

  Append:

```sql
-- A show-if list the loader accepts: an array of objects, each
-- `eq`/`ne`/`filled` with a string field, `gte`/`lte` with a string field and
-- a number value, or `any` with a non-empty array of non-empty groups, each
-- itself an acceptable list.
create or replace function vitally_private.intake_show_if_ok(p_show_if jsonb) returns boolean
language plpgsql immutable security definer set search_path='' as $$
declare c jsonb; g jsonb;
begin
 if jsonb_typeof(coalesce(p_show_if, '[]'::jsonb)) <> 'array' then
  return false;
 end if;
 for c in select value from jsonb_array_elements(coalesce(p_show_if, '[]'::jsonb)) loop
  if jsonb_typeof(c) is distinct from 'object' then
   return false;
  end if;
  case coalesce(c->>'op', '')
   when 'eq', 'ne', 'filled' then
    if jsonb_typeof(c->'field') is distinct from 'string' then
     return false;
    end if;
   when 'gte', 'lte' then
    if jsonb_typeof(c->'field') is distinct from 'string' or jsonb_typeof(c->'value') is distinct from 'number' then
     return false;
    end if;
   when 'any' then
    if jsonb_typeof(c->'groups') is distinct from 'array' or jsonb_array_length(c->'groups') = 0 then
     return false;
    end if;
    for g in select value from jsonb_array_elements(c->'groups') loop
     if jsonb_typeof(g) is distinct from 'array' or jsonb_array_length(g) = 0
      or not vitally_private.intake_show_if_ok(g) then
      return false;
     end if;
    end loop;
   else
    return false;
  end case;
 end loop;
 return true;
end;
$$;
```

// One clause per " AND ": `field = value`, `field ≠ value`, `field` is filled,
// or rule `name`, which expands to that rule's conditions. An unknown rule
// reads as unreadable.
function parseCondition(text) {
  return text.split(" AND ").flatMap((clause) => {
    let m = clause.match(/^rule `([a-z_]+)`$/);
    if (m) return Object.hasOwn(RULES, m[1]) ? structuredClone(RULES[m[1]]) : [null];
    m = clause.match(new RegExp(`^\`(${ID}) (=|≠) (${VALUE})\`$`));
    if (m) return [{ field: m[1], op: m[2] === "=" ? "eq" : "ne", value: m[3] }];
    m = clause.match(new RegExp(`^\`(${ID})\` is filled$`));
    if (m) return [{ field: m[1], op: "filled" }];
    return [null];
  });
}
